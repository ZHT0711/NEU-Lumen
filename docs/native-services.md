# 原生校园服务

目前提供第一阶段适配，功能仍未与五个原站完整对齐。完整验收需要按登录账号逐项核对原站菜单、子页面、查询、表单、附件及提交后的结果。下表记录当前实现范围，网页跳转项仍属于待补齐的原生功能。

服务大厅的“原生服务”栏默认折叠，展开后按紧凑卡片选择服务。搜索时显示匹配入口，进入后支持左右滑动切换。原学校应用图标、收藏及链接继续打开学校原站。原生入口集中在此处，避免在个人页和成绩页重复设置。

另增加校园资讯、校园日程和本机下载中心，共八项原生工具。卡面采用八幅独立矢量简笔画：何世礼教学馆、校园饮食、校门、银杏与长椅、校园信件、火箭广场、体育馆与跑道、图书馆书桌。插画为装饰性创作，饮食和人文图案不代表特定商家或具体校园活动。

缴费页展示已接入的校园账户数据，不能据此推断学宿费是否欠缴。接口没有返回进度、未读状态或余额时显示未读取/未知，不用 0 冒充。

表单与订单视图读取已登录 WKWebView 的实际 DOM，并保留学校原表单、隐藏字段和页面事件。原生编辑支持转回原网页继续填写。操作前展示表单内容及对应订单上下文，复核文档、字段、隐藏字段与订单内容，再触发一次对应的学校控件。结果以学校返回页面为准。文件上传、富文本和动态表单扩展仍需使用网页控件。当前读取每表前 200 行，并显示截断提示，可继续通过学校分页读取。

邮箱通过独立脚本世界调用学校客户端同源接口，包括 `user:getAttrs`、`mbox:listMessages`、`getAllFolders`、`searchMessages`、`readMessage.jsp`、`mbox:updateMessageInfos` 与写信初始化 `compose.jsp`。协议依据学校公开部署的 `coremail/bundle/{ $,X,M,C }.157e8.js` 客户端实现核对。已读、星标与移动操作在写入前后复核邮箱身份，网络中断时提示先刷新核对。首次邮箱地址不匹配校园学号时要求用户确认关联。回复和转发先取得学校创建的写信标识，再打开对应编辑窗口。实际发送由用户在学校编辑窗口完成。正文显示解码后的文字，附件由原学校页面通过 WebKit 下载管理保存。

登录按校园账号和服务隔离，使用 WKWebsiteDataStore 与 Keychain；注销清除对应会话并轮换 WebKit 配置。身份切换、页面跳转、账号代次改变时丢弃旧请求。学校会话过期仍需正常认证，不能保证永久免登录。邮箱列表不另行写入磁盘缓存。

iOS 26 的 Liquid Glass 用在切换导航控件，数据内容保持清晰的系统分组背景；减少透明度与增强对比度时提供不透明样式。使用系统动态字体、VoiceOver 标签和至少 44pt 的切换目标，不自动轮播。

Nightly 图片来自同次构建的实际模拟器页面，使用仅存在于临时 Debug 副本的合成数据，不表示真实校园账号联调或实体 iPhone 验证。

2026-11-13 的连接检查中，WebVPN 入口返回 HTTP 403，缴费和申请详情跳转学校认证。五项服务的完整网页功能对齐仍待真实账号核验，尤其是多步申请、动态联动字段、材料上传、订单分页与支付结果、富文本发送、通讯录及邮箱设置。离线协议回归与模拟器合成表单检查分别覆盖接口编码、身份隔离、必填校验、订单内容变化、一次操作限制与返回网页继续填写。

设计依据：[Apple HIG Materials](https://developer.apple.com/design/human-interface-guidelines/materials)、[Liquid Glass](https://developer.apple.com/documentation/SwiftUI/Applying-Liquid-Glass-to-custom-views)、[Live Activities](https://developer.apple.com/design/human-interface-guidelines/live-activities)。

2026-11-14 补齐缴费项目中心与订单中心入口。缴费服务使用公网缴费站点及其正常 CAS 跳转。原生页面支持学校 `onclick` 项目入口，并在异步加载后更新列表。认证、验证码、二维码和 canvas 页面保留可见原网页。后台观察内容变化时保留正在编辑的表单与操作核对状态。

原生服务栏默认折叠，搜索会显示匹配入口。培养方案详情支持层级大纲，大字体环境默认使用大纲，图节点尺寸随动态字体调整。

电费缴纳按钮和首页电费卡片直达项目 414 的 `openPayElecPagesDbdx51414E039.html`。正常认证落回缴费大厅时，仅自动恢复这一个已确认的只读目标一次；不预填支付金额、不创建订单、不自动付款。

电费查询房间按校园账号保存在本机，原生缴费与校园卡共用该选择。电费专页对明确表示完整 7 位房间码的空输入框预填，保留学校已有值与用户修改；未识别的楼栋、寝室分级控件不拆码猜填。查询草稿在切换服务时保留，可恢复已保存房间；换号清空旧草稿。修改房间可取消，查询失败保留同一房间的上一份结果和时间。真实账号及实体 iPhone 的缴费预填仍需联调。

校园码使用独立原生展示页，沿用现有学校入口和正常登录。只显示学校当前页面实际生成、可核对学工号的码图与原文状态；无法确认账号、码图为空、离线、切后台或学校页面跳转时清除展示。原生页定期重读，超过保守展示时限重新向学校读取，不把本机读取时间当作学校签发的有效期，不生成或持久化身份/付款码。学校定制出码页面、不可读码图或认证可在同一会话的学校页面继续。协议与界面回归使用合成图形，不代表真实账号出码、通行或支付已验证。

资讯页切换服务后保留同一账号的频道、关键词和列表；刷新失败保留旧结果，重试从失败的那一页继续。服务目录增加下拉刷新与加载失败重试，切换账号会清空旧筛选与页面状态。

缴费流水支持月份切换、关键词、消费/充值筛选和明细查看，展示该月实际已读取的记录及截断提示；切月不会把上一月的行标成新月份。已登录的项目与订单页面在同一账号内保留 WebKit 历史，原生表单草稿仅在同一文档、字段、隐藏订单上下文均未变化时恢复，导航或换号即失效；不把支付金额和订单内容写入持久化草稿。

邮箱正文补充收件人、抄送、时间、可识别正文链接与附件大小，支持重试、前后封及继续加载。学校明确提供的普通内部 MIME 附件可从原生正文发起，由同一 WebKit 会话交给下载中心；下载前重新核对邮箱和附件，登录标识不返回原生模型或写入下载记录。网盘、加密及未知类型附件仍需学校页面。刷新原子更新已加载的多页列表，中途失败保留原列表，换条件后不混用旧搜索结果。正文缓存仅存在当前账号的内存中，限 12 封。

办事进度保留已展开分页，返回、刷新和错误重试不会丢掉后页；整批刷新失败时保留原结果和成功时间。指南图示使用当前登录会话和访问线路读取，失败时提供重试与学校页面入口。服务目录只有在结果匹配当前筛选时展示，换账号清除筛选。WebVPN 资源搜索包含学校域名与已支持的校内 IP 地址，切网后重新检测；界面区分保存了会话与服务实际可用性。

提醒与后台刷新见 [说明](reminders.md)。自定义灵动岛支持 26 个 SF Symbols 主图标及 `{sf:...}` 行内符号，去掉内容中的变量/缓存来源说明，将标题、图标、正文和计时信息分清层次。

网络切换时比较实际使用接口、连通状态及网关变化，短暂断开后等待链路稳定再恢复会话。连续切网合并到最后一次有效变化，并通知已失败或进行中的读取重新请求。首页、应用目录、课表、成绩、校园账户、教务查询与学习任务保留已有数据，按需重读；原生办事和邮箱也响应恢复事件。网页仅在失败或仍在加载、原请求可按 GET 恢复且页面没有编辑内容时自动恢复。请求身份、账号代次与新请求标识继续校验。

移动流量连接失败的补充修复：网络变化仅比较正在使用的接口类型和实际网关，不因未使用接口的增减反复取消读取。切网时保留 Cookie 并重建 HTTP 连接池，拒绝旧网络的迟到响应和 Cookie；校园探测要求学校页面特征或已知站内跳转，不把普通 HTTP 200 / 运营商登录页当成校园直连。切网恢复先解析线路并重试读取，只有业务明确报告认证失效时才续登，不先等待整套续登。GET/HEAD 瞬断可短暂重试一次，POST、用户取消、超时和证书错误不在底层自动重放。原生协议回归覆盖这些规则；实体 iPhone 的 Wi-Fi/4G/5G 切换仍需实际网络核验。
